## 2. 项目背景与目标

### 2.1 业务痛点
1. 客户在企业微信客户群中接收大量重复性咨询（产品、价格、流程、售后），人工客服逐条回复，耗时且响应不及时，非工作时间无人应答。
2. 已有产品资料/FAQ 散落在 Word、PDF 文档中，无法被群内成员即时检索利用。
3. 人工客服回答口径不统一，新人培训成本高；常见问题被反复提问却没有沉淀机制。
4. 客户希望以可控成本（<3 万元）先验证机器人客服价值，再决定是否投入二期。
5. 部分同类客户（尤其中小客户）不想自建服务器、也没有运维人力，希望像使用普通 SaaS 一样按订阅方式开通使用——因此产品同时提供「私有化部署」与「SaaS 托管」两种交付形态。

### 2.2 项目目标
- 在企业微信客户群中提供 7×24 小时自动问答能力，常见问题由机器人即时作答，回答依据来源于客户自有知识文档。
- 建立"未命中问题沉淀 → 人工补录 → 知识库完善"的半自动学习机制，使知识覆盖率随运营持续提升。
- 满足企业微信合规接入与基本内容安全要求（验签、出站敏感词过滤、密钥安全管理）。
- 25 个工作日内完成开发、部署与验收，交付可独立运维的成品系统；支持两种交付形态：**A 私有化部署**（部署到客户自有服务器，数据不出域）与 **B SaaS 托管**（我方云上租户实例，免运维、按订阅付费）。两种形态共用同一套产品功能与代码基，区别仅在部署位置、运维责任与付费方式。

### 2.3 成功指标（验收期实测为准，以下为目标值而非合同承诺）
| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 机器人响应时延 P95 | ≤ 8 秒（@触发至消息送达群内） | 验收期日志统计（依赖 DeepSeek API 实际时延） |
| FAQ 命中率（知识库覆盖范围内问题） | ≥ 80% | UAT 用 50 条预置标准问测试集统计，以实测为准 |
| 非触发消息静默率 | 100%（不误答） | 群消息抽测 |
| 低置信度拒答转人工提示正确率 | ≥ 95%（无胡编答案） | UAT 越界问题测试集 |
| 未命中问题落库完整率 | 100% | 对比触发日志与落库记录 |
| 系统可用性（验收陪跑期 7 天） | ≥ 99%（不含第三方 API/企微侧故障） | 陪跑期监控记录 |

## 3. 范围说明

### 3.1 In Scope（本期）
1. 企业微信官方 API（自建应用）接入，客户群消息收发。
2. @机器人 / 关键词触发机制，非触发消息静默不响应。
3. FastGPT 私有化部署（含 pgvector、bge embedding）+ DeepSeek 云 API 的智能问答。
4. 知识库文档上传（Word/PDF/Markdown）、自动切分、向量化索引。
5. 单群/单人会话上下文隔离，近 5 轮上下文，超时重置。
6. 低置信度拒答并提示转人工。
7. 未命中问题落库（问题/群/时间/置信度得分）并可导出 Excel；人工在 FastGPT 后台补录问答对。
8. 安全最低集：回调验签、出站敏感词过滤（本地词库可维护）、密钥 .env 管理。
9. 客户云服务器（4C8G）Docker Compose 一键部署，域名 + HTTPS。
10. 交付物：成品系统部署包（Docker Compose 一键部署，绑定客户指定服务器使用）、部署手册、操作手册、补录培训 1 次、上线后 7 天陪跑、3 个月质保。不含源码。
11. 【增项包】入站多媒体消息处理（FR-9）：@机器人 + 图片自动识别转文字提问；语音/视频/文件消息引导话术兜底并落库。
12. 【增项包】素材回复（FR-10）：知识库可关联微信公众号文章链接、文档、视频素材，命中后随答案一并发送给用户。
13. 【增项包】历史聊天记录导入（FR-11）：批量导入历史微信会话记录（企微会话存档导出 / 客服整理表格），自动抽取问答语料、脱敏与敏感剔除后，经人工审核确认入知识库，用于机器人上线初期的知识库冷启动。
14. 双交付形态支持（FR-8 扩展）：同一产品同时支持「私有化部署」与「SaaS 托管」两种形态交付，功能一致、数据模型一致，选择权在客户。
15. 【增项包 C】SaaS 托管形态与租户管理（FR-12）：租户实例开通与隔离（每租户独立实例/独立数据库/独立域名）、租户配额与计量（群数/消息量/知识库容量）、订阅有效期管控与续期、租户注销与数据删除（含导出）；自带自助注册与在线支付属二期。
16. 【增项包 D】本地模型接入与部署（FR-13）：大模型与 embedding 可整体内嵌到系统内部（数据不出域），与云 API 三档可切（cloud/hybrid/local），切换仅需改配置；含 vLLM 部署、模型选型联调与切换演练，GPU 服务器由客户自备。

### 3.2 Out of Scope（二期规划，本期不做）
| 项 | 说明 |
|---|---|
| 独立运营后台 / 数据看板 | 本期运营操作均在 FastGPT 自带后台完成 |
| 学习闭环自动化（自动审核、自动入库） | 本期仅半自动：落库 → 人工补录 |
| 多模态问答（语音/视频内容解析、图片闲聊理解） | 本期仅含增项 FR-9 的"@机器人图片识别转提问"；语音/视频内容解析与任意图片理解属二期 |
| 私有化大模型部署 | 本期支持**单机本地模型接入（增项包 D，FR-13）**；GPU 集群级高可用部署、多模型路由、模型微调属二期 |
| 多租户 / SaaS 化 | 本期**支持 SaaS 托管形态（每租户独立实例，物理隔离）**；共享实例多租户（同一套基础设施内逻辑隔离）、自助注册、在线支付、按量计费属二期 |
| 微信个人号（非企微）接入 | 无官方合规通道，不做 |
| 历史语料「零审核」自动学习 | 本期必须经人工审核后入库；无审核的全自动学习属二期（历史人工回复质量参差，直接学习会把不当表述带进自动回复） |
| 会话存档实时接入 / 在线质检 | 本期仅支持离线导出文件批量导入，不做实时流式接入与实时质检 |

## 4. 角色与使用场景

### 4.1 角色定义
| 角色 | 说明 |
|---|---|
| 群成员 | 企业微信客户群中的客户，提问者 |
| 群主/客服 | 群内人工客服，处理机器人拒答/转人工的问题 |
| 知识运营员 | 客户方指定人员，负责上传文档、查看未命中记录、补录问答对 |
| 管理员 | 我方交付及客户方 IT，负责部署、配置、密钥与词库维护 |
| 平台运营方（SaaS 形态） | 我方运营人员，负责租户开通/续期/配额调整/平台运维与升级（仅 SaaS 形态存在） |
| 租户管理员（SaaS 形态） | SaaS 租户侧的管理员，可查看本租户用量与订阅信息、导出本租户数据，不可跨租户访问 |

### 4.2 用户故事
- **US-1（群成员）**：作为群成员，我在群里 @机器人 提问"退货流程是什么"，希望 8 秒内得到依据公司资料的回答，以便不用等待人工客服。
- **US-2（群成员）**：作为群成员，我用关键词（如"请问"开头或命中预设触发词）提问，也能获得回答，以便在忘记 @ 时仍可使用。
- **US-3（群成员）**：作为群成员，当我追问"那运费呢"，机器人能结合我上一问理解语境作答，无需重复完整问题。
- **US-4（群成员）**：作为群成员，当问题超出知识范围时，我希望机器人明确告知"不知道"并提示联系人工，而不是编造答案。
- **US-5（群主/客服）**：作为群主，机器人在群内不主动发言、不响应普通聊天，避免打扰群内正常沟通。
- **US-6（知识运营员）**：作为知识运营员，我可定期导出未命中问题 Excel，把高频未命中问题整理成问答对补录进 FastGPT，使命中率逐周提升。
- **US-7（知识运营员）**：作为知识运营员，我可在 FastGPT 后台上传新版产品文档（Word/PDF/Markdown），系统自动切分并生效，无需开发人员介入。
- **US-8（管理员）**：作为管理员，我可维护出站敏感词库，命中敏感内容的回答被拦截并替换为安全话术，保证群内内容合规。
- **US-9（群成员）**：作为群成员，我把产品界面截图 @机器人 发问"这个怎么操作"，机器人能识别图中文字并结合知识库作答，不必费劲打字描述。
- **US-10（群成员）**：作为群成员，当我询问"有没有详细教程"时，机器人除文字答案外，还能把知识库里的公众号文章链接、说明书 PDF 或操作视频直接发到群里。
- **US-11（知识运营员）**：作为知识运营员，我希望把过去和客户的历史聊天记录批量导入，经系统清洗、脱敏和我的审核后变成知识库，让机器人一上线就能解答常见问题，而不是等未命中记录一条条积累。
- **US-12（客户决策者）**：作为客户方决策者，我希望能选择部署形态：数据敏感时选私有化部署（数据不出域、一次性投入），想快速上线、不想自己运维服务器时选 SaaS 订阅，两种形态功能一致、可后期迁移。
- **US-13（平台运营方）**：作为我方平台运营，我能为每个客户开通独立租户实例（独立数据库/独立域名/独立密钥）、设定群数与用量配额、在订阅到期前提醒续期，并在租户注销时完成数据导出与删除，确保租户之间严格隔离。

## 5. 功能性需求

### FR-1 企业微信接入
- **描述**：通过企业微信自建应用接入客户群消息回调，实现群消息接收与被动/主动回复。
- **业务规则**：
  1. 仅处理已配置客户群的消息事件；非目标群消息忽略。
  2. 回调接口必须完成企微验签（msg_signature + timestamp + nonce + AES 解密），验签失败一律拒绝并记录日志。
  3. 回调须在企微要求时限内返回成功响应，问答处理异步进行，避免企微判定超时重推。
  4. 企微消息去重：同一 MsgId 不重复处理。
  5. access_token 统一缓存与刷新，不落地明文存储于代码库。
- **验收标准**：
  - Given 已配置回调 URL 与密钥，When 企微推送一条加密群消息，Then 系统验签通过并解析出发言人、群 ID、文本内容。
  - Given 一条伪造签名消息，When 到达回调接口，Then 返回拒绝且日志记录，不进入问答流程。
  - Given 同一 MsgId 消息被重推 2 次，Then 机器人仅回复 1 次。

### FR-2 触发与路由
- **描述**：判定群消息是否触发机器人应答；未触发消息完全静默。
- **业务规则**：
  1. 触发条件（满足其一）：a) 消息 @机器人；b) 文本命中可配置触发关键词/前缀列表。
  2. 触发关键词清单通过配置维护（管理接口热加载，见概要设计 M2）。
  3. 机器人自身发送的消息、其他机器人消息不触发，静默忽略；未 @机器人的多媒体消息（图片/语音/视频/文件/表情）不触发，静默忽略。带 @机器人 的图片消息进入图片识别流程（FR-9 规则 2）；带 @机器人 的语音/视频/文件消息回复引导话术并落库（FR-9 规则 3）。
  4. 触发后的问题文本需剥离 @ 标记与触发词后再进入问答。
  5. 非触发消息不做任何回复、不 @任何人、不产生未命中落库。
- **验收标准**：
  - Given 群成员发送"@机器人 保修期多久"，Then 机器人进入问答流程，问题文本为"保修期多久"。
  - Given 普通聊天消息未 @机器人且未命中关键词，Then 机器人无任何响应且无任何落库。
  - Given 群内发送一张图片，Then 机器人静默。
  - Given 群成员 @机器人 发送一张图片，Then 进入图片识别流程（FR-9）。
  - Given 触发词配置为"客服："，When 发送"客服：怎么开发票"，Then 触发问答且问题为"怎么开发票"。

### FR-3 智能问答
- **描述**：基于 FastGPT 知识库检索（bge embedding + pgvector）+ DeepSeek 云 API 生成回答。
- **业务规则**：
  1. 回答必须基于知识库检索结果生成；通过 FastGPT 提示词约束禁止脱离资料作答。
  2. 检索置信度低于阈值（默认 0.75，可配置，以实测调优为准）时执行拒答：回复固定话术"抱歉，这个问题超出了我的知识范围，已为您记录，稍后由人工补充解答。"，并将该问题记入未命中库（见 FR-6）。
  3. 空问题、纯标点、长度超过 500 字的问题，回复引导话术，不调用模型。
  4. DeepSeek API 调用失败/超时（硬超时 15s 可配置，仅作用于异步补发路径；同步路径性能预算 5.5s）时，启用通义千问 fallback 重试 1 次；双通道均失败回复"系统繁忙，请稍后重试或联系人工客服"，并记录错误日志。
  5. 回答长度适配群聊场景：超过企微单条文本上限时自动分段发送；命中时附来源引用（最多 2 条）。
- **验收标准**：
  - Given 知识库已收录"保修期 1 年"，When 提问"保修多久"，Then 回答包含"1 年"且 P95 响应 ≤8s（以实测为准）。
  - Given 知识库无"竞品类"内容，When 提问越界问题，Then 回复拒答话术且该问题落库，无编造内容。
  - Given 模拟 DeepSeek API 超时，Then 自动切换通义 fallback；双通道均失败时用户收到"系统繁忙"提示，日志含错误详情。
  - Given 回答超过 2000 字，Then 分段发出且顺序正确。

### FR-4 上下文管理
- **描述**：支持同一会话内多轮追问理解。
- **业务规则**：
  1. 会话维度 = 群 ID + 用户 ID，单群单人隔离；A 的上下文对 B 不可见。
  2. 上下文窗口为最近 5 轮问答（1 轮 = 1 问 + 1 答）。
  3. 会话超时时间默认 10 分钟（600s，可配置），滑动续期，超时后上下文重置，按新会话处理。
  4. 上下文仅用于生成时的对话历史，不影响检索权限与知识范围。
- **验收标准**：
  - Given 用户 A 问"这款产品多少钱"得到回答后，When 2 分钟内追问"运费呢"，Then 回答能关联同一产品语境。
  - Given 用户 A 的会话进行中，When 用户 B 提问，Then B 不受 A 上下文影响。
  - Given 用户 A 最后一次提问距今超过 10 分钟，When 再次提问，Then 按新会话处理（不携带历史）。
  - Given 连续 6 轮问答，When 第 7 轮提问，Then 仅携带最近 5 轮历史。

### FR-5 知识库管理
- **描述**：知识运营员在 FastGPT 后台维护知识库，系统按文档自动切分与向量化。
- **业务规则**：
  1. 支持上传 Word（.docx）、PDF（.pdf）、Markdown（.md）格式文档；单文件大小上限 20MB。
  2. 采用 FastGPT 自动切分 + bge embedding 向量化，写入 pgvector；切分参数（chunk 大小/重叠）使用默认推荐值，可按实测调优。
  3. 支持直接录入 QA 问答对（用于人工补录场景，见 FR-6）。
  4. 文档更新/删除后索引同步更新，问答即时生效，无需重启服务。
  5. 文档内容治理责任归客户方；涉密/敏感资料由客户自行脱敏后上传。
  6. 【FR-11 增项】经历史聊天记录导入生成的问答对存放于知识库中的独立数据集（"历史语料"），与人工整理的"客服知识库"分离，支持按批次整体下线。
- **验收标准**：
  - Given 上传一份含 30 个 FAQ 的 docx，Then 后台显示切分完成且检索测试可命中相关段落。
  - Given 删除某文档，When 提问仅该文档覆盖的问题，Then 机器人执行拒答。
  - Given 手工录入一条 QA 对，Then 对应提问可按该答案回复。

### FR-6 未命中学习与人工补录
- **描述**：未命中问题自动落库并可导出，运营员人工补录形成半自动学习闭环。
- **业务规则**：
  1. 凡触发拒答（FR-3 规则 2）的问题，自动写入未命中库，字段：问题原文、群 ID、提问人 ID（企微 userid）、时间、检索置信度得分、处理状态。
  2. 提供按时间范围导出 Excel（.xlsx）功能（管理接口 + Basic Auth，见概要设计 M5）。
  3. 运营员在 FastGPT 后台将未命中问题整理为 QA 对补录；补录后同类问题应能命中。
  4. 同一问题多次未命中仅多次记录，不做自动聚合（聚合分析属二期）。
  5. 未命中记录保留期默认 90 天（可配置）。
- **验收标准**：
  - Given 发生 3 次拒答，Then 未命中库存在 3 条记录且字段完整。
  - Given 导出最近 7 天记录，Then 生成 xlsx 且行数与库内一致。
  - Given 某未命中问题已补录 QA 对，When 再次提问该问题，Then 正常作答且不再落库。

### FR-7 出站敏感词过滤
- **描述**：机器人所有出站消息经本地敏感词库过滤后发送。
- **业务规则**：
  1. 词库为本地可维护文件（txt），支持增删词条，文件变更热加载生效。
  2. 回答命中敏感词时：不发送原回答，替换为固定话术"抱歉，该内容不便回复，请联系人工客服。"，并记录审计日志（原问题、命中词，不含原回答全文）。
  3. 过滤仅针对出站消息；入站消息不过滤（入站内容治理由企微/客户群管理负责）。
  4. 初始词库交付时提供样例，正式词条由客户方维护确认。
- **验收标准**：
  - Given 词库含词 X，构造使模型回答含 X 的场景，Then 群内收到替换话术，原文未发出，审计日志完整。
  - Given 正常回答不含敏感词，Then 原样发出，过滤不引入可感知延迟。

### FR-8 部署与配置（双交付形态）
- **描述**：同一套成品系统支持两种交付形态——**A 私有化部署**（部署在客户自有云服务器，Docker Compose 一键拉起，数据不出域）与 **B SaaS 托管**（部署在我方云上的租户专用实例，客户免运维）。两种形态功能完全一致，均由域名 + HTTPS 对外提供企微回调。
- **业务规则**：
  1. **形态 A（私有化部署，基线）**：目标环境客户云服务器 4C8G，Linux（建议 Ubuntu 22.04），Docker + Docker Compose；组件为适配层、FastGPT、PostgreSQL（pgvector）、MongoDB、Redis、Nginx，全部容器化，单 `docker compose up -d` 可启动；部署与运维责任归客户方，我方提供部署手册与远程指导。
  2. **形态 B（SaaS 托管，增项包 C，详见 FR-12）**：系统部署在我方云上，**每个租户一套独立实例**（独立容器组、独立数据库、独立 Redis 实例、独立域名与证书），租户间数据物理隔离、互不可见；客户无需自备服务器与运维人力，通过订阅方式使用。
  3. 两种形态共用同一代码基与同一功能集（含 FR-9/FR-10/FR-11 各项能力），差异仅在部署位置、运维责任方、授权与付费方式；**支持形态迁移**：私有化 → SaaS（导出知识库与配置后重新开通租户）、SaaS → 私有化（导出数据 + 在客户服务器部署）均可完成，迁移工具与操作由我方提供。
  4. 所有密钥（企微 CorpID/Secret/Token/AESKey、DeepSeek API Key、FastGPT API Key）通过 .env 注入，严禁写入代码库与镜像；形态 A 下 .env 模板随部署包交付，形态 B 下由租户在管理界面配置、加密存储。
  5. 对外通过域名 + HTTPS（Nginx 反代 + 证书）暴露企微回调；FastGPT 后台限制访问来源（形态 B 下每个租户独立后台入口）。
  6. 提供部署手册（形态 A）与租户操作手册（形态 B）：含环境准备、启动、停止、升级、备份（数据卷）与常见故障排查。
  7. 升级策略：形态 A 由客户在维护窗口执行升级（我方提供升级包与说明）；形态 B 由我方按计划滚动升级，提前 3 个工作日通知租户，选择低峰时段并支持回滚。
- **验收标准**：
  - Given 一台干净的 4C8G 服务器与手册，When 按手册操作，Then 2 小时内完成部署并通过企微回调验证（形态 A）。
  - Given 检查镜像与代码库，Then 无任何明文密钥。
  - Given 重启服务器，Then `docker compose up -d` 后服务全部恢复且知识库数据不丢失。
  - Given 形态 B 新开一个租户，Then 30 分钟内完成实例开通（独立库/独立域名/绑定企微应用）并可正常问答（详见 FR-12）。
  - Given 同一套知识库数据，When 从形态 A 迁移到形态 B，Then 迁移后问答效果一致（同一测试集命中率差异 ≤ 5 个百分点）。

### FR-9 入站多媒体消息处理【增项包】
- **描述**：处理群成员 @机器人 发送的图片（识别转文字后进入问答链路）与语音/视频/文件消息（引导话术兜底），消除"发图/发文件无响应"的体验断点。
- **业务规则**：
  1. 仅处理 @机器人 的多媒体消息；未 @机器人 的多媒体消息维持静默（与 FR-2 一致）。
  2. 图片消息：适配层经企微素材下载接口按 media_id 下载（企微 3 天有效期内，单张 ≤10MB），调用视觉模型（通义 qwen-vl，复用现有通义 fallback 通道账号）提取图中文字并归纳为一句咨询问题，随后进入 FR-3 正常问答链路（置信度判定/拒答/来源引用全部复用）；识别失败或超时（硬超时 10s）回复引导话术："抱歉，暂时没看懂这张图片，麻烦用文字简述一下您的问题～"。
  3. 语音/视频/文件消息：不做内容解析，回复固定话术："抱歉，我暂时无法直接查看视频/文件，请用文字描述问题（可注明文件名），或 @人工客服 协助。"同时写入未命中库（miss_record 新增 media_type 字段标记 voice/video/file），供运营侧观察高频媒体类诉求，作为二期多模态立项依据。
  4. 图片识别产生的问题与答案同样进入会话上下文（FR-4）与出站敏感词过滤（FR-7）；识别出的问题文本记入问答日志便于排查。
- **验收标准**：
  - Given 知识库含某产品界面操作说明，When 群成员 @机器人 发送该界面截图，Then 机器人基于图中文字识别结果作答（或按置信度规则正常拒答）。
  - Given 发送一张模糊无关图片，When 识别无有效内容，Then 回复引导话术且不编造答案。
  - Given 群成员 @机器人 发送一个视频，Then 收到引导话术且未命中库落库记录 media_type=video。
  - Given 未 @机器人 的图片/视频/文件，Then 机器人静默且不落库。

### FR-10 素材回复【增项包】
- **描述**：知识库答案可关联素材（微信公众号文章链接、文档、视频），命中后机器人将素材随答案一起发送到群内，支持"文章怎么办理""发我一份说明书""有没有操作视频"类诉求。
- **业务规则**：
  1. 素材库：知识运营员经管理接口（Basic Auth，与未命中导出一致）上传/维护素材，分三类：链接（公众号文章等 URL）、文件（Word/PDF 等文档）、视频（mp4）。文件与视频存储于客户服务器素材目录并纳入每日备份，元数据入素材表（见概要设计 asset 表）。
  2. 知识关联：在 FastGPT 后台录入/编辑 QA 对或文档答案时，以约定标记 `[[素材:编号]]` 引用素材（写法在操作手册与培训中覆盖）；一条答案最多关联 2 个素材。
  3. 回复行为：命中答案含素材引用时，机器人先发送文本答案（剥离标记、含来源引用），随后逐个发送素材消息并 @提问人：链接 → 文本消息（素材标题 + URL，公众号文章可点击跳转）；文件 → 经企微临时素材上传后以文件消息发送；视频 → 以视频消息发送。
  4. 大小限制：文件 ≤20MB、视频 ≤10MB（企微消息接口上限）；超限素材降级为文本链接（客户提供可下载 URL 时）或提示"素材过大，请联系人工客服获取"。
  5. 素材外发消息中的文本部分（标题/说明）经敏感词过滤（FR-7）；文件与视频内容不做解析与过滤，合规责任归客户方（与知识文档治理口径一致）。
  6. 素材发送失败（接口异常/素材文件缺失/已停用）不影响文本答案送达：补发一条"素材发送失败，可联系人工客服获取"提示并记 WARN 日志。
- **验收标准**：
  - Given 答案关联 1 个公众号文章链接素材，When 命中该问题，Then 用户先收到文本答案，随后收到含可点击链接的消息。
  - Given 答案关联 1 个 5MB 的 PDF 素材，When 命中，Then 群内收到可下载的文件消息，内容与上传原件一致。
  - Given 素材文件被误删，When 命中该答案，Then 文本答案正常送达且收到降级提示，日志含 WARN。
  - Given 运营员上传 8MB mp4 视频并关联，When 命中，Then 群内收到可播放的视频消息。

### FR-11 历史聊天记录导入（知识库冷启动）【增项包】
- **描述**：支持将历史微信会话记录（企业微信会话存档导出文件，或客服整理成表格的往来对话）批量导入，系统自动清洗、抽取"客户提问—客服回答"语料、脱敏与敏感内容剔除，经运营员审核确认后写入知识库，使机器人在上线初期即具备解答能力，解决"知识库冷启动没有语料、上线前几周命中率低"的问题。
- **业务规则**：
  1. **导入来源与格式**：① 企业微信「会话存档」导出文件（JSON/CSV，走企业官方合规通道）；② 客服整理的对话表格（.xlsx / .csv / .txt，需含时间、说话方（客户/客服）、内容三列，可选含会话/群标识列）。单批上限 5 万条消息或 200MB，超出分批导入。
  2. **自动清洗**：剔除系统消息（入群/退群/撤回提示）、占位消息（表情/图片/语音/视频/文件）、机器人自身消息、刷屏与重复内容（同一发送方 60 秒内重复内容仅留 1 条）、无实义短消息。
  3. **问答配对（QA 抽取）**：以"客户提问 → 客服回答"为配对单元。规则：客户侧消息视为问，其后同一会话 30 分钟内客服侧首条实质回复视为答；同一话题的多轮追问合并为 1 对（问取首条，答取最终结论）；无法配对的单边消息进入"未配对池"由人工判定，不自动入库。
  4. **脱敏（强制）**：入库前对手机号、身份证号、银行卡号、详细地址、姓名（姓氏 + 称谓/全名模式）自动打码为占位符（如 `[手机号]`）；群 ID/客户标识哈希化存储；导入的原始文件与原始记录在处理完成后自动删除，不留存。
  5. **敏感与不当内容剔除（强制）**：命中黑名单（价格与折扣承诺、优惠力度、内部制度与政策、法律与赔偿承诺、竞品贬损、脏话等）的问答对**不自动入库**，标记为"需人工复核"。历史人工回复可能包含超出权限的承诺，直接学习会把风险带进自动回复。
  6. **人工审核门禁（强制）**：抽取结果生成审核清单（Excel），列含问答内容、来源会话标识、发生时间、脱敏/命中标记、建议动作；运营员逐条勾选"保留 / 修改后保留 / 丢弃"，系统**仅导入审核通过的条目**，未审核条目一律不参与检索。
  7. **去重**：批次内按内容指纹幂等去重（重复导入不产生重复数据）；导入前与现有知识库做相似度比对，与已有知识高度相似的条目提示"已有近似知识"并默认不入库。
  8. **入库方式**：审核通过的问答对写入知识库中独立数据集"历史语料"（与现有"客服知识库"分离），来源标注为"历史记录导入"，答案引用时可展示来源，便于区分人工整理知识与历史语料。
  9. **生效与可回滚**：审核确认后即时生效，无需重启服务；支持按导入批次一键"下线"，将该批次导入的全部条目移出检索，其他知识不受影响。
  10. **导入统计**：每批次输出统计报表——解析条数、配对成功数、脱敏条数、敏感剔除条数、审核通过数、实际入库数、去重跳过数，用于评估历史数据的可用价值。
  11. **任务化执行**：导入为后台异步任务，提交后返回任务编号，可查询进度（解析中/配对中/待审核/入库中/已完成/失败）；失败条目单列并可重试，任务不阻塞群内问答。
- **验收标准**：
  - Given 一份 1 万条消息的历史会话导出文件，When 提交导入，Then 10 分钟内完成解析与配对，并生成含问答对清单与统计数字的审核文件。
  - Given 审核清单中 100 条勾选"保留"、50 条勾选"丢弃"，When 确认入库，Then 知识库新增 100 条、来源显示"历史记录导入"，被丢弃的 50 条不入库且不可被检索。
  - Given 历史消息含手机号/身份证信息，When 完成入库，Then 知识库内容中相应信息已打码，且服务器上原始导入文件已删除。
  - Given 历史对话中含价格承诺/折扣类内容，When 抽取完成，Then 该条被标记"需人工复核"，未自动入库。
  - Given 同一批次执行"下线"，Then 该批次全部条目不可被检索，其他知识库内容正常命中。

### FR-12 SaaS 托管形态与租户管理【增项包 C】
- **描述**：为不想自建服务器与运维的客户提供 SaaS 托管形态：系统部署在我方云上，**每个租户一套独立实例**（独立容器组、独立数据库、独立域名与证书），由平台运营方统一完成租户开通、配额管理、订阅续期与升级维护，租户开箱即用。
- **业务规则**：
  1. **租户开通**：平台运营方在平台控制台创建租户（租户名称、联系人、订阅周期、配额档位），系统自动完成：实例编排（适配层 + FastGPT + PostgreSQL + Redis + MongoDB 容器组）、数据库与初始化、独立域名与 HTTPS 证书、独立密钥（企微/LLM/后台口令）、授权证书签发（绑定该租户实例、有效期与订阅期一致）。开通目标时长 ≤ 30 分钟。
  2. **租户隔离（强制）**：每租户独立实例与独立数据存储，网络层互不可达；跨租户检索必须 0 命中；租户管理员/知识运营员权限严格限于本租户；平台侧管理人员不默认可读租户知识库正文。
  3. **配额与计量**：按租户配置配额——群数量上限、日消息量、知识库容量（文档数/QA 对数）、素材存储。按日统计并输出报表（租户自见用量 + 平台总览）。达 80% 预警通知；达 100% 拒新群接入或限流，**已服务群不受影响**（与群数上限规则一致）。
  4. **订阅有效期管控**：订阅到期前 30/15/7 天提醒；到期后进入 7 天宽限期（只读：群内问答正常，不可修改知识库、不可新增群）；宽限期结束后进入受限模式——群内仅回复"服务已到期，请联系服务商续期"，不进入问答链路、不消耗 LLM 调用；续费后热生效、无需重建实例。
  5. **租户注销与数据删除**：注销需运营方与租户双方确认；执行顺序：全量数据导出（知识库/素材/未命中记录/配置，加密包交付租户）→ 租户确认收货 → 7 天后删除实例与数据（含备份）→ 出具数据删除确认单；法律法规要求留存的除外。
  6. **数据归属与使用边界**：租户数据归租户所有，我方仅为受托处理方；承诺不跨租户使用、不用于模型训练、不对外提供；租户可随时导出自身数据。
  7. **故障域与可用性**：单租户实例故障不影响其他租户；实例级健康检查 + 自动重启；平台级监控告警（实例存活、资源水位、问答失败率、LLM 调用异常）；计划内维护提前 3 个工作日通知并选低峰时段。
  8. **安全运维与审计**：运维人员访问租户实例须审计留痕（操作人/时间/动作/原因）；除故障排查并经租户书面同意外不查看租户知识库与问答正文。
  9. **能力对齐与升级**：SaaS 租户享有与私有化版本一致的功能；版本升级由平台统一执行，租户无需操作，支持升级回滚。
  10. **资源档位与备份**：按租户所选档位（标准/增强）分配资源；每日备份保留 7 天，订阅期内提供 1 次按需数据恢复。
- **验收标准**：
  - Given 平台运营方创建新租户并配置订阅，When 完成开通，Then 30 分钟内租户可完成企微绑定并正常问答，且实例、数据库、域名、证书均为该租户独有。
  - Given 两个租户各自独立的知识库，When 租户 A 的成员提问只存在于租户 B 知识库的问题，Then 租户 A 无法得到该答案（跨租户 0 命中，抽测 ≥ 20 条）。
  - Given 租户用量达配额 100%，When 新群尝试接入，Then 拒绝接入并告警，已接入群服务正常。
  - Given 订阅到期并已过 7 天宽限期，When 群内 @机器人 提问，Then 仅收到续期提示话术，无 LLM 消耗。
  - Given 租户申请注销并完成导出确认，When 执行删除，Then 实例与数据（含备份）被删除并出具删除确认单。

### FR-13 本地模型接入与部署【增项包 D】
- **描述**：大模型与 embedding 能力可整体内嵌到系统内部（本地部署推理服务），满足数据不出域要求；与云 API 并存，三档可切，切换仅需修改配置、无需改代码。GPU 服务器由客户自备（T4/A10/L4 或纯 CPU 兑底档）。
- **业务规则**：
  1. **三档模型通道**（配置项 MODEL_MODE）：cloud（基线，DeepSeek 云 API）/ hybrid（本地优先，超时或故障自动切云兑底）/ local（全本地，故障回繁忙话术，不出域）。
  2. **接入方式**：本地推理引擎（vLLM，GPU；或 Ollama，CPU 兑底）暴露 OpenAI 兼容端点，接入问答平台渠道；本地 embedding（bge-m3，CPU 即可）。模型基线 Qwen2.5-7B/14B-Instruct（可按需换同接口模型）。
  3. **交付内容**：推理与 embedding 服务部署（容器化）、模型选型与加载、问答平台渠道配置、三档切换配置与演练、压测调优（含超时/并发参数适配）、交付含升级与切换操作说明。
  4. **性能预期（目标值，实测为准）**：GPU 档（7B）文本问答 P95 ≤15s；CPU 兑底档仅适用日活 <500 场景。本地档时延高于云档属预期取舍，以数据不出域优先。
  5. **降级行为**：hybrid 档本地不可用自动切云；local 档本地不可用回固定话术并告警，**不外发任何数据**。
  6. **索引重建约束（需客户知晓）**：embedding 模型切换必须全量重建向量索引（约 0.5–2 小时，选低峰执行）；LLM 通道切换无此限制，可热切。
  7. 不含：GPU 集群高可用部署、多模型路由、模型微调训练（属二期）。
- **验收标准**：
  - Given 本地推理服务部署完成，When 在问答平台配置渠道并切到 local 档，Then 群内问答正常且服务器无任何 LLM 云端出站流量（防火墙验证）。
  - Given hybrid 档且本地服务停止，When 群内提问，Then 自动切云作答，恢复后切回本地。
  - Given local 档且本地服务停止，When 群内提问，Then 仅收到繁忙话术，无数据外发。
  - Given 7B GPU 档，When 按标准问测试集回归，Then P95 ≤15s（实测口径）。

## 7. 界面与交互需求

本期不新增自研界面，交互载体为**企微群消息**与 **FastGPT 自带后台**。

### 7.1 群内交互流程
1. 群成员 @机器人 或使用触发词提问 → 2. 机器人异步处理 → 3. 机器人在群内回复答案（@提问人）。
   - 命中：直接回复答案（含来源引用），必要时分段。
   - 未命中：回复拒答话术（提示转人工），问题落库。
   - 系统异常：回复"系统繁忙"话术。
   - 敏感词命中：回复替换话术。
4. 非触发消息：机器人全程静默。

- 知识运营员日常使用范围：知识库文档上传/更新/删除、QA 对录入、检索命中测试；未命中记录通过管理接口导出（入口与账号在操作手册中说明）。
- 运营员不得修改应用编排中的模型参数与提示词（需调整时联系交付方，质保期内免费微调）。
- 管理员使用范围：账号管理、密钥轮换、敏感词库维护、日志查看。

### 10.2 UAT 流程
1. **准备**（T-3 天）：客户方提供测试群、测试账号、50 条标准问测试集（含 ≥ 10 条越界问题）；双方确认测试计划。
2. **执行**（2 天）：按 AC-1~AC-15 逐项执行并记录结果（未勾选的增项包对应 AC 不纳入验收）；缺陷分级（阻断/严重/一般）。
3. **修复与回归**：阻断/严重缺陷修复后回归通过方可进入下一步；一般缺陷记录并约定修复时限（质保期内）。
4. **签字验收**：全部 AC 通过或经双方确认的豁免项清单签字后，进入 7 天陪跑期；陪跑期可用性达标即项目验收完成，转入 3 个月质保。

| QA 抽取 | 从历史对话中自动识别并配对出"客户提问—客服回答"单元，形成可入库的问答语料 |
| 私有化部署 | 系统部署在客户自有服务器/云环境内，数据不出客户掌控范围；客户自行运维 |
| SaaS 托管 | 系统部署在交付方云上，以租户实例方式向客户提供，客户按订阅付费、免自建服务器与运维 |
| 租户实例 | SaaS 形态下为单个客户独立部署的一套完整系统（独立容器组/数据库/域名/密钥），与其他租户物理隔离 |
| 平台控制面 | SaaS 形态下交付方管理租户的平台（租户开通、配额、订阅、升级、监控），不存储租户知识库正文 |
| 宽限期 | SaaS 订阅到期后的 7 天只读期（问答可用、不可改知识与加群），过后进入受限模式 |
| 本地模型档 | 大模型与 embedding 服务部署在客户服务器内（vLLM/Ollama + Xinference），数据不出域；与云 API 三档可切（cloud/hybrid/local） |
| 视觉模型（qwen-vl） | 通义千问视觉语言模型，用于识别用户 @机器人 发送图片中的文字与内容 |
| 会话上下文 | 同群同人最近若干轮问答历史，用于理解追问 |
| P95 | 95% 请求的响应时延不高于该值 |
| UAT | 用户验收测试 |
