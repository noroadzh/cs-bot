# 部署包使用说明

| 项 | 内容 |
|---|---|
| 适用文件 | `cs-bot-deploy-0.1.0.tar.gz`（后续版本把 `0.1.0` 换成实际版本号） |
| 适用环境 | x86_64 Linux，已安装 Docker 24+ 与 Docker Compose v2 |
| 形态 | 私有化单机。SaaS 客户不用这个包 |

解压后先看根目录的 `使用说明.md`（与本文件相同）。安装执行 `sudo ./deploy/setup.sh`。包内还有《部署手册》和《用户使用手册-私有化版》。

这个包已经带上适配层镜像和分步安装脚本。`nginx`、`FastGPT`、`PostgreSQL`、`MongoDB`、`Redis` 不在包里，第一次执行 `./deploy/build-images.sh` 时从公网拉取。证书、`license.lic` 和填好的 `.env` 也不在包里，要在服务器上自己放。

工作目录始终是 `/opt/cs-bot`。

## 1. 解压前放在手边

| 材料 | 用途 |
|---|---|
| 本压缩包 | 脚本、配置、适配层镜像 |
| `fullchain.pem`、`privkey.pem` | HTTPS 证书 |
| `license.lic` | 交付方签发的授权 |
| 企微 CorpID、AgentId、Secret、Token、EncodingAESKey（正好 43 位） | 回调 |
| DeepSeek Key、通义 Key | 问答 |
| 运维电脑的公网 IP | 管理接口和 FastGPT 后台白名单 |
| 已解析到这台机器的域名 | 企微回调地址 |

服务器需要能访问这些镜像仓库：`nginx:1.27-alpine`、`registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt:v4.8.17`、`pgvector/pgvector:pg16`、`mongo:7`、`redis:7-alpine`。海外机器把 `.env` 里的 `FASTGPT_IMAGE` 设为 `ghcr.io/labring/fastgpt:v4.8.17`。

Ubuntu 22.04 上还没有 Docker 时：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo timedatectl set-timezone Asia/Shanghai
docker compose version
```

## 2. 解压并校验

把压缩包上传到服务器后执行。包内顶层目录名是 `cs-bot-deploy-0.1.0`。

```bash
sudo mkdir -p /opt
sudo tar -C /opt -xzf cs-bot-deploy-0.1.0.tar.gz
sudo mv /opt/cs-bot-deploy-0.1.0 /opt/cs-bot
cd /opt/cs-bot
sha256sum -c SHA256SUMS.txt
```

每一行都要是 `OK`。出现 `FAILED` 就不要继续，重新要包。

## 3. 准备镜像

这一步加载包内的适配层镜像，并拉取另外五个公共镜像。

```bash
cd /opt/cs-bot
./deploy/build-images.sh
docker images | grep -E 'cs-bot-adapter|nginx|fastgpt|pgvector|mongo|redis'
```

结束时应能看到本地标签 `cs-bot-adapter:latest`。公共镜像拉取失败时，先检查服务器出网，再重跑同一条命令。

## 4. 按步骤填写并部署

在终端执行。向导共 8 步，每步先说明参数的作用和填错或事后修改的影响，再写入 `/opt/cs-bot/.env`。

```bash
cd /opt/cs-bot
sudo ./deploy/setup.sh
```

只看步骤、不写文件、不启动：

```bash
./deploy/setup.sh --steps
```

向导会问这些项。口令由向导用 `openssl rand -hex 24` 生成并只显示一次。`REDIS_PASSWORD` 保持空。

若要自己编辑 `.env`，仍可：

```bash
cd /opt/cs-bot
cp .env.template .env
chmod 600 .env
openssl rand -hex 24
```

`openssl` 运行 4 次，把 4 段结果分别填进下面 4 个口令。口令用十六进制，避免 `/`、`+` 写进数据库连接串。`REDIS_PASSWORD` 保持空，不要填。

每一项的用途和取值来源写在 `.env.template` 里该变量上方的注释中。复制成 `.env` 后注释还在。口令类是自己用 `openssl rand -hex 24` 生成的，不是脚本输出，也不是从 FastGPT 页面抄的。企微和模型 Key 从对应控制台抄。没有注释要求修改的项保持模板原值。

生产环境必须把模板里的两个 mock 开关改成 `false`：

```dotenv
USE_MOCK_LLM=false
USE_MOCK_LICENSE=false

WECHAT_CORP_ID=ww开头的企业ID
WECHAT_AGENT_ID=1000002
WECHAT_AGENT_SECRET=自建应用Secret
WECHAT_TOKEN=企微接收消息Token
WECHAT_ENCODING_AES_KEY=正好43位的EncodingAESKey

FASTGPT_BASE_URL=http://fastgpt:3000
FASTGPT_API_KEY=fastgpt-pending-key
FASTGPT_ROOT_PASSWORD=第1个openssl结果
FASTGPT_FILE_TOKEN=第2个openssl结果

LLM_PRIMARY_BASE_URL=https://api.deepseek.com/v1
LLM_PRIMARY_API_KEY=sk-你的DeepSeekKey
LLM_FALLBACK_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_FALLBACK_API_KEY=sk-你的通义Key

POSTGRES_PASSWORD=第3个openssl结果
ADMIN_USER=admin
ADMIN_PASSWORD=第4个openssl结果
ALLOWED_ADMIN_IPS=你的运维公网IP/32

FASTGPT_ADMIN_PORT=8443
FASTGPT_ADMIN_ALLOW_CIDRS=
REDIS_PASSWORD=
```

`FASTGPT_API_KEY` 先写至少 8 位的占位符。真实 Key 要等 FastGPT 起来之后才能创建，见第 7 步。回调地址只配在企微后台，不写进 `.env`。

## 5. 放入证书和授权

```bash
cd /opt/cs-bot
sudo mkdir -p deploy/nginx/certs license
sudo cp /path/to/fullchain.pem deploy/nginx/certs/fullchain.pem
sudo cp /path/to/privkey.pem deploy/nginx/certs/privkey.pem
sudo cp /path/to/license.lic license/license.lic
sudo chmod 600 deploy/nginx/certs/privkey.pem license/license.lic
```

不用改 `deploy/nginx/nginx.conf`。域名用 DNS 指到这台机器即可。

## 6. 启动

`sudo ./deploy/setup.sh` 写完配置并放入证书后，会自己执行预检和启动。已经手工填好 `.env`、证书和授权时，也可以直接：

```bash
cd /opt/cs-bot
./deploy/install.sh --check
sudo ./deploy/install.sh
curl -kfsS https://127.0.0.1/healthz
```

`--check` 通过时打印 `预检通过`，此时还没有启动容器。启动成功时本机 `/healthz` 返回 200，并列出 6 个容器：`nginx`、`adapter`、`fastgpt`、`pg`、`mongo`、`redis`。

超时就看适配层日志：

```bash
docker compose -f deploy/docker-compose.yml logs --tail=80 adapter
```

改完 `.env` 后要执行 `docker compose -f deploy/docker-compose.yml up -d`。`restart` 不会重新读取环境变量。

## 7. 打开知识库并写回 Key

把运维网段写进 `.env` 的 `FASTGPT_ADMIN_ALLOW_CIDRS`，例如 `203.0.113.20/32`。安全组只给这个网段放行 8443，然后：

```bash
cd /opt/cs-bot
sudo ./deploy/install.sh
```

浏览器打开 `https://<域名>:8443`，用户名 `root`，口令是 `FASTGPT_ROOT_PASSWORD`。建一个知识库和应用，复制应用的 API Key，写回 `.env` 的 `FASTGPT_API_KEY`，再执行：

```bash
cd /opt/cs-bot
docker compose -f deploy/docker-compose.yml up -d adapter
```

## 8. 接通企业微信

部署完成后执行 `./deploy/setup.sh --after`，按打印的对照表改企微后台和本机 `.env`。摘要如下。

企微管理后台 → 该自建应用 → 接收消息：

- URL：`https://<域名>/wecom/callback`
- Token、EncodingAESKey 与 `.env` 里的 `WECHAT_TOKEN`、`WECHAT_ENCODING_AES_KEY` 相同

保存成功后，把应用拉进测试群，`@机器人` 问一个知识库里有的问题。

## 9. 常用命令

在 `/opt/cs-bot` 下执行：

```bash
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f --tail=200 adapter
docker compose -f deploy/docker-compose.yml stop
./deploy/backup.sh
```

备份产物在 `backup/<时间戳>/`。日常运维、升级和排障见《部署手册》。群内怎么用见《用户使用手册-私有化版》。
